# FITA conformance corpus

A small set of `.fita` files with **known, recorded conformance status**, used to
score implementations of the FITA format.

```bash
python corpus/build_corpus.py            # regenerate
python corpus/build_corpus.py --verify   # prove it is reproducible and correct
```

18 files, ~975 KB. Every file is generated by [`build_corpus.py`](build_corpus.py)
from analytic data — no RNG, no wall-clock timestamps.

Two kinds of stability, and they are not the same:

- **Semantic stability — always enforced.** Every file must still validate to
  the conformance level and the exact set of failing clauses recorded in
  [`MANIFEST.json`](MANIFEST.json). This holds across astropy versions and is
  what an implementation is actually scored against.
- **Byte stability — enforced within a toolchain.** Regenerating with the
  astropy/numpy/Python versions recorded under `toolchain` in the manifest
  reproduces the files byte for byte. A *different* astropy may serialise the
  same content to different bytes — card formatting and padding shift between
  releases — so `--verify` reports the difference and compares semantics only.

The distinction was found the hard way: the corpus was generated under astropy
7.2.0, and a clean install pulling astropy 8.0.1 produced different bytes for
identical, equally conformant files. An unqualified "byte-reproducible" claim
would have been false the first time anyone upgraded.

## Why a generator, not a folder of files

A corpus of opaque blobs cannot be reviewed, cannot be regenerated when the
standard moves, and cannot explain itself. The script *is* the corpus; the files
are its output. Both are committed — the archived artifact should contain the
actual bytes a third-party implementer tests against — and `--verify` proves the
two agree.

## The four tiers

| Tier | Files | What it is for |
|---|---|---|
| **`conformance/`** | 15 | Positive/negative pairs, one per clause the validator enforces. This is the tier an implementation is *scored* against. |
| **`legacy/`** | 1 | A v1.0 file as they were actually written. Makes D-1 grandfathering demonstrable rather than asserted. |
| **`science/`** | 1 | A three-band field with depth, blend modes, uncertainty and false-colour mapping — what the format is *for*. |
| **`roundtrip/`** | 1 | Every attribute a format bridge could silently drop, in one file. |

### Negative fixtures isolate one clause each

Each is built by writing a **conformant** file and then breaking exactly one
thing, so a failure points at a single clause rather than a general mess:

| File | Breaks |
|---|---|
| `neg_missing_fita_vis.fita` | §6.2 — required layer keyword removed |
| `neg_alpha_no_bzero.fita` | §6.3 — the v1.0 wrapped-alpha defect |
| `neg_alpha_bunit_alpha16.fita` | §7 — the retired invalid unit |
| `neg_bad_blend_code.fita` | §8.1 — unknown blend code must raise, not fall back |
| `neg_nlayers_mismatch.fita` | §4.2 — `FITANL` disagrees with the FLUX count |
| `neg_split16_declared.fita` | §6.4 — the deleted packing mode |
| `neg_zsc_not_finite.fita` | §8.2 — non-numeric stereo scale |
| `neg_access_format_overclaim.fita` | §3 — the unregistered `+alpha` MIME type |
| `neg_adj_unknown_type.fita` | §8 — unknown `ADJ_TYPE` |
| `neg_adj_bad_json.fita` | §8 — unparseable `PARAMS` |

> Note: negative fixtures are minimal files without provenance, so they also
> fail the §9 `FITA_META` SHOULD. The manifest records every failing clause, so
> the intended one is never inferred.

## The round-trip tier

`roundtrip/transfusion_reference.fita` exists because a format bridge — the
ImageJ2 / PyImageJ route, or any second implementation — loses attributes
*silently*. This project has found that failure four times (`SPLIT16`, wrapped
alpha, the lost `visible` flag, `to_records()` restoring default adjustments),
and in every case the loss looked like success.

The file therefore carries, deliberately and at once: a hidden layer
(`visible=False`), a layer with **absent** depth, a disabled adjustment, a
variable-length response curve, NaN-blanked pixels, uncertainty and mask
planes, stereo geometry, and full provenance.

`MANIFEST.json` carries a `survival_spec` naming what must come back:

- flux bit-exact — **NaN-aware**: compare NaN masks and finite pixels separately
- alpha in `0..65535` with `BZERO=32768`, not signed and wrapped
- per-layer `visible`, including `False`
- per-layer `blend_mode` and `opacity`
- per-layer `zdepth`, including **absent** (must not become `0.0`)
- companion `UNCERT_*` / `MASK_*` planes
- `FITA_ADJ` order, `enabled` flags, and typed parameter values
- `FITA_ADJ` variable-length parameters (curve points, response arrays)
- `FITA_ZSC` / `FITA_ZRF` / `FITA_ZAN`
- ObsCore columns and their `TUCDn` annotations

## Using it to score an implementation

1. Open every file. **Nothing may crash** — including `legacy/`.
2. For each, report a conformance level; compare to `expected_level`.
3. For files that fail, compare your failing clauses to `failing_clauses`.
4. Round-trip `roundtrip/transfusion_reference.fita` and check every line of
   `survival_spec`.

An implementation that passes tiers 1–2 reads FITA correctly. One that also
passes tier 4 can be used as a *bridge* without losing science.

## Provenance of the corpus itself

`MANIFEST.json` records, per file: tier, purpose, the clause it exercises, the
expected and actual conformance level, every failing clause, size and SHA-256.
The generator refuses to write a fixture whose validator verdict disagrees with
its own label — a corpus that could drift from its labels would be worse than
none.
